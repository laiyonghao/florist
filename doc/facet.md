# florist.contrib.facet（片面模式 / 动态属性）

`facet` 当前主要是概念性模块（仓库内只有 README 占位），用于描述一种“动态属性建模”的方向：

- 不同类型对象（商品/文章/用户等）拥有不同的属性集合
- 属性集合可配置、可扩展，而不需要频繁改表/改模型

> 代码位置：`florist/contrib/facet/`

## 片面模式（理论）

“片面（facet）”可以理解为：

- **核心对象**：如商品 `Product`
- **片面定义**：某一类商品需要的属性集合（比如酒：容量/度数；衣服：尺码/面料）
- **片面值**：某个对象在某个片面上的具体取值

常见实现手段：

- EAV（Entity-Attribute-Value）模型
- JSON Schema + JSONField
- 动态表单（后台配置字段，前端根据 schema 渲染）

优点：

- 适合 SKU、商品属性、表单系统、低代码等场景

代价：

- 查询与索引更复杂
- 数据一致性需要额外约束

## 当前状态

- 仅有 README 描述，没有可用的模型/管理后台/接口代码。

如果要把 `facet` 落地为可用模块，建议优先补齐：

1. `FacetDefinition`：描述属性 schema（字段名、类型、校验、UI 组件）
2. `FacetValue`：保存某对象的属性值（建议按对象类型+对象 id 分片索引）
3. 管理后台：可视化配置 schema、预览表单
4. 查询策略：常用字段做“冗余索引”或倒排索引
